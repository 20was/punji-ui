Live charts are cheaper per tick, with published numbers (docs/PERFORMANCE.md, `npm run bench:charts`). `CandlestickChart` keeps each candle's checks per candle object, draws candles as memoised marks and memoises its hidden table rows, and computes a simple moving average only where a mark is drawn: a tick on the forming candle at 1,000 candles commits in about 1 ms instead of 8 to 14 ms, so 1,000 ticks a second are applied instead of about 90. `PerformanceChart` builds its number formatter once, memoises table rows and lists the latest 500 dates in its hidden table (new optional `tableLimit` and `labels.truncated`, as `CandlestickChart`): at 100,000 dates a mount takes about 0.12 s instead of 8.4 s and an update about 18 ms instead of 4.1 s. The shared quantity formatter used by `CandlestickChart` and `DepthChart` is built once. `Sparkline` is memoised (still server-safe) and reduces long series without a set and a sort. `Live` caches its reduced-motion query and stops copying its frame set every frame. Public APIs are unchanged apart from the new optional props. A Next.js App Router consumer build (`npm run check:nextjs`) now runs in CI. Size budgets: sparkline 890 to 920 B, candlestick-chart 5.33 to 5.6 kB, performance-chart 4.28 to 4.5 kB gzip (the memoised marks and rows).

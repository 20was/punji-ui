# Component inventory: Punji Web versus Punji UI

Date: 2026-10-31. Facts only; anything not verified is marked **unverified**.
Companion plan: [docs/INTEGRATION.md](docs/INTEGRATION.md). Machine-readable name-level
inventory: [docs/audit/inventory.json](docs/audit/inventory.json) and
[docs/audit/component-matrix.md](docs/audit/component-matrix.md) (both generated by
`npm run audit:web`).

## Method and scope

- Consumer inspected read-only: `/Users/bishwas/Documents/Punji-Web/punji-web` at commit
  `f6df01a149318af373b7b0605edd2f446e9722f7`. Its working tree also had uncommitted edits to
  `src/design/pages/display.tsx` and `src/design/pages/inputs.tsx`; the kit directory itself was
  clean. `npm run audit:web` reads the working tree, so the generated files reflect that.
- Package inspected: this repository on a branch based on `dbb01aa` (`feat(calculations)`), package
  `@punji/ui` version `0.0.0`, not yet published (release is gated by the repository variable
  `UI_NPM_RELEASE_ENABLED`, see [.github/workflows/release.yml](.github/workflows/release.yml)).
- Where punji-web keeps shared UI: **`src/components/kit/`** (167 modules, excluding `index.ts`),
  exposed to the app through the alias `@punji/ui` (see [docs/INTEGRATION.md](docs/INTEGRATION.md),
  section 1). Other shared-looking code lives in `src/components/{data,ui,charts,layout,market,stocks,
  statements,fundamentals,learn,auth}`, `src/hooks`, `src/lib`, `src/me/{hooks.ts,shared.tsx,desk,lib,
  data}` and `src/theme`.
- Per kit module I compared the implementation with the punji-ui counterpart (normalised diff with
  imports and comments removed, then read by hand), counted importing files by static `import ... from`
  (named imports from `@punji/ui`, `@punji/ui/<sub>`, or a relative `kit` path; dynamic `import()`
  strings were searched only for the dead-code check), and read the header comment and exported props.
  API summaries come from `src/design/props.generated.json` in punji-web (generated by
  `scripts/design-props.mjs`; whether it is current was **not verified**).
- "Usage" counts files, not call sites. `app` excludes `src/design` (the docs site), which is counted
  as `docs`. A kit module used only by other kit modules shows under `kit`.

   `formatFigure` versus punji-ui `format/` and `nepal/*`. The first reads reader-language global state.

   (0 references) versus `kit/Figures.tsx` Delta/Figure (15 app files).

   `me/desk/Skeleton.tsx` (311 lines, about 11 files).

5. **Media-query hooks**: 21 files call `window.matchMedia` directly (5 inside the kit); punji-ui has
   `useMediaQuery`.

   private copy in `design/pages/dataviz.tsx`. **Resolved** in punji-ui: one `Sparkline` (`src/sparkline`), the small

7. **Icon sets**: `ui/icons.tsx`, `ui/NavIcon.tsx` (CSS masks), `kit/NavIcon.tsx`, `kit/SettingIcon.tsx`,

   `kit/Disclosure.tsx`; `ui/CtaPanel.tsx` versus `kit/CtaBand.tsx`.
9. **Dead look-alikes**: `ui/Badge.tsx` (versus StatusPill), `ui/StatCard.tsx` (versus MetricTile/StatTile),
   `ui/TableScroll.tsx` (versus DataTable): all with zero references.
10. **Error and empty states**: `data/DataError.tsx`, `kit/RetryNote.tsx` (16 files), `kit/InlineState.tsx`
    (7), `me/shared.tsx` ErrorState, `fundamentals/States.tsx`, plus page-local `EmptyStart` in
    `me/pages/Portfolio.tsx` and `Empty` in `me/pages/Fundamentals.tsx`.

## Quality issues observed

Verified by reading source or by search:

- `components/ui/ScreenCard.tsx`: 1054 lines, 204 inline style objects, 13 literal hex colours
  (for example `#d4a017` and `#b8bcc4` gold/silver dots), not token-based.
- `components/ui/AnnotatedShot.tsx` and `components/data/*`: inline style objects and colour fallbacks
  instead of classes (`AnnotatedShot` has a `#c0392b` fallback).
- Literal hex in TSX is otherwise limited to the Google logo paths in `auth/SignInPanel.tsx` (4),
  `theme/ThemeContext.tsx` (2) and `pages/Dividends.tsx` (1). Literal colours in CSS: `me-theme.css`
  148 (theme token values), `base.css` 49, `kit.css` 45 (not individually reviewed); `kit.css`
  includes `#000` (8) and `#ffffff` (5) outside tokens.
- `data/Delta.tsx` renders the missing marker as an ASCII hyphen and announces direction in English only.
- Three skeletons and five icon sets (see duplicates above).
- 29 `outline: none` occurrences in `src/styles`; whether each is replaced by a `:focus-visible` style
  was **not verified**.
- A same-line search for `<div|span ... onClick` in components, pages and me found 3: two are
  `aria-hidden` scrims, one stops propagation in `me/pages/portfolio/RowActions.tsx` (multi-line JSX
  was not searched).
- Seven kit modules have no `aria-` or `role` attribute in source (Checkbox, FactList, GroupPill,
  RatingChip, RuleSentence, SecurityTitle, SummaryFigure). Several are text only; semantics were not
  audited individually.
- `Button` and the other link components in punji-web use `react-router-dom` directly; punji-ui requires
  a `linkComponent`. External links: punji-web opens a new tab with `rel="noopener noreferrer"`; punji-ui
  renders a plain `<a>` (behaviour change on migration unless restored upstream).
- Class-name collision risk: punji-ui and punji-web both define `.kit-*` selectors (for example
  `.kit-card`) but punji-ui reads `--pu-*` tokens in `@layer punji.*` whereas punji-web's unlayered
  `kit*.css` reads `--color-*`, `--space-*` and so on. See INTEGRATION.md section 3.
- Missing states in punji-web kit: not systematically audited (**unverified**). `FinancialTable` in
  punji-ui models ready/loading/empty/error states; `DataTable` in punji-web has none of them.

Financial correctness note: portfolio, XIRR, sale and fee maths in punji-web run on `number` values and
backend-vendored contract code (`src/contracts/finance/*`, never edited by hand per `AGENTS.md`).
punji-ui `calculations/*` is bigint and exact. They are not interchangeable and must not be swapped
without a separate decision.

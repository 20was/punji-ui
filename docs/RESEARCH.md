## Nepal conventions and sources

- [Unicode CLDR Nepali locale data](https://github.com/unicode-org/cldr/blob/main/common/main/ne.xml) and [UTS #35 number rules](https://www.unicode.org/reports/tr35/tr35-numbers.html) inform Intl use. English uses en-IN grouping; Nepali uses ne-NP. Western digits are the ecosystem default; Devanagari is opt-in. Language does not silently change stored numbers.
- [Government project financial statements hosted by the World Bank](https://documents1.worldbank.org/curated/en/099060423064029507/pdf/P16020708f501f0800964f0a00927cf55b9.pdf) give FY 2078/79 as Shrawan 1, 2078 through Ashadh 32, 2079, and the AD start as July 16, 2021. This anchors a test; fiscal years derive from the BS month, never a fixed July day.
- Instants explicitly use IANA `Asia/Kathmandu`. Calendar dates are `{year, month, day}` with one-based months. Conversion and date formatting never infer the host timezone.
- Nepali BS month names are documented constants. Full application copy requires native editorial review; the showcase language control changes number/date formatting only.

## Licence/dependency policy

MIT remains the package licence. The converter is installed as a dependency with its upstream MIT licence; no third-party source is vendored. React peers are MIT. Existing font names are fallbacks, not bundled font binaries. Referenced Apache projects would require preservation of licence/NOTICE obligations if source were adopted later. AGPL examples are domain research only. Review new runtime dependencies individually for licence, transitive graph, release evidence, type exports, security and bundle cost; zero dependencies is not a reason to invent fragile calendar arithmetic.

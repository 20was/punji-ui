## Decisions

1. Keep canonical Gregorian ISO date-only values across both calendars. A user
   can switch AD/BS without corrupting transaction, birthday or reporting dates.
   This also lets applications outside Nepal use the same core API.
2. Reuse the existing vetted BS converter through the Nepal calendar boundary.
   BS month length is validated against its table, never guessed by arithmetic.
   Gregorian ordinal movement uses UTC and explicitly handles years below 100.
3. Keep selection math pure and separate from React, labels and overlay behavior.
   Discriminated TypeScript props prevent mixing single/range/multiple values.
4. Use existing Field, Select, Button, semantic tokens and portal compositions.
   The Field trailing action is additive and preserves its default markup.
5. Revised after owner visual review: compose Calendar in the existing shared
   Popover. Use a portal, viewport flipping/clamping, scroll/resize observation,
   Escape restoration and normal Tab continuation. Do not dim, inert or lock
   the whole page for routine date entry. Avoid a new positioning dependency.
6. Use direct numeric year entry instead of rendering 9999 options. Month changes
   clamp month-end days; unavailable dates remain focusable but never selectable.
7. Expose strict input validation and canonical hidden form fields. Do not log
   entered values, fetch account data, or embed actual customer information in docs.
8. Support caller-controlled locale/week start/labels with English/Nepali defaults.
   Do not claim universal calendar, timezone, RTL or screen-reader certification.

## Size accounting

Calendar/date-picker JS, declarations and CSS are additive features. Existing
primitive and utility budgets stay unchanged, including Button imported from root.
Aggregate gzip limits increase from 22.3 to 28.8 kB JS and 11.8 to 12.5 kB CSS;
the unpacked tarball cap increases from 400 to 430 KiB. Dedicated Calendar,
DatePicker and calendar CSS limits make future feature growth reviewable. The
converter is shared, and selective imports remain tree-shakeable. Measured sizes
are emitted by `npm run size` and `npm run check:package`.

labels remain accessible; keyboard guidance is visually hidden rather than a
paragraph in every picker. Direct year entry retains the full supported date
range without generating thousands of options. Touch days stay 44px.

positioning and the existing media-query hook; aggregate budgets and other primitive budgets remain unchanged. The shared
Popover budget is 1.9 kB (measured ~1.9 kB), covering portal positioning,
viewport-aware scrolling and keyboard continuation. Popover's portal/width/positionAnchor options are additive.

## Input boundary and anchoring regression checks

The portal's existing unlayered button sizing overrode the new action-slot height.
The shared Field now constrains the action with max-height and an inset boundary,
keeping hover paint and keyboard focus inside the input. The picker measures the
actual control, excluding label and hint. Its gap is 6px above/below. If neither
side fits, constrain panel height to the available side instead of moving it away
from the field. The calendar caption and range actions remain reachable while
scrolling; scrolling the reference offscreen dismisses the panel.

Browser regression checks measure input/action containment and popup gap for
single, range and constrained appointment examples at both widths and themes.
